# terraform-provider-lsmrust

A Terraform provider for declaring hosted [lsm-rust](https://github.com/zvdy/lsm-rust) tenant databases as infrastructure-as-code, plus a mock control-plane API to develop and test it against.

lsm-rust itself is an embedded storage engine with a RESP data server and has no management API. The real multi-tenant control plane does not exist yet, so this repo ships an in-memory stand-in with the API shape the provider expects.

```hcl
resource "lsmrust_database" "orders" {
  name = "orders-prod"
  tier = "dedicated"

  resource_limits {
    memory_mb = 4096
    disk_gb   = 100
  }

  backup_policy {
    schedule  = "0 */6 * * *"
    retention = "14d"
  }
}

resource "lsmrust_access_key" "app" {
  database_id = lsmrust_database.orders.id
  scopes      = ["read", "write"]
}
```

## Layout

```
main.go                  provider entrypoint (registry.terraform.io/zvdy/lsmrust)
mock-control-plane/      runnable mock API server
internal/mockserver/     mock API implementation (also used in-process by tests)
internal/client/         typed HTTP client for the control-plane API
internal/provider/       provider, resources, acceptance tests
examples/                example configs; examples/main is the smoke-test config
docs/                    generated by tfplugindocs
scripts/smoke.sh         end-to-end loop against the real terraform CLI
```

```
terraform CLI --gRPC--> terraform-provider-lsmrust --HTTP/JSON--> control plane
                                                               (mock today)
```

## Requirements

- Go 1.27.1+ (older Go versions with `GOTOOLCHAIN=auto` download it automatically)
- Terraform 1.5+ (developed against 1.13)

## Running the mock control plane

```sh
go run ./mock-control-plane -addr :8080 -provision-delay 2s -api-key devkey
```

| Flag | Default | Meaning |
|---|---|---|
| `-addr` | `:8080` | Listen address |
| `-provision-delay` | `2s` | How long a database stays `pending` after create, or `updating` after a resize |
| `-api-key` | `$LSMRUST_API_KEY` | If set, every request needs `Authorization: Bearer <key>` |

All state lives in process memory. Restart the process to reset it.

### API

| Method | Path | Notes |
|---|---|---|
| `POST` | `/v1/databases` | Returns `201` with `status: "pending"` |
| `GET` | `/v1/databases` | List |
| `GET` | `/v1/databases/{id}` | |
| `PATCH` | `/v1/databases/{id}` | Partial update. A `tier` change returns `409`. A `resource_limits` change moves status to `updating` |
| `DELETE` | `/v1/databases/{id}` | Cascades to the database's access keys |
| `POST` | `/v1/databases/{id}/access_keys` | Returns the `secret`. This is the only time it is ever returned |
| `GET` | `/v1/access_keys/{id}` | No `secret` |
| `PATCH` | `/v1/access_keys/{id}` | Replace `scopes` |
| `DELETE` | `/v1/access_keys/{id}` | |

Errors are JSON: `{"error": "..."}`.

## Using the dev build with Terraform

Build the binary:

```sh
go build -o ~/.terraform.d/dev/terraform-provider-lsmrust .
```

Point Terraform at it with a CLI config file, without touching `~/.terraformrc`:

```hcl
# dev.tfrc
provider_installation {
  dev_overrides {
    "registry.terraform.io/zvdy/lsmrust" = "/home/you/.terraform.d/dev"
  }
  direct {}
}
```

```sh
export TF_CLI_CONFIG_FILE=$PWD/dev.tfrc
export LSMRUST_ENDPOINT=http://localhost:8080
export LSMRUST_API_KEY=devkey
cd examples/main
terraform plan
terraform apply
terraform destroy
```

With `dev_overrides`, skip `terraform init`: it fails because `zvdy/lsmrust` is not in the public registry. If you need `init` to work, for example because the config also uses other providers, add a `filesystem_mirror` for the provider as `scripts/smoke.sh` does.

The provider block accepts `endpoint` and `api_key`. If either is unset or empty, the `LSMRUST_ENDPOINT` or `LSMRUST_API_KEY` environment variable is used instead.

## Testing

```sh
go test ./...          # unit + acceptance tests
TF_ACC=0 go test ./... # unit tests only
make smoke             # build, run the mock, and drive the real terraform CLI
```

- **Unit tests** (`internal/client`, `internal/mockserver`) run against canned `httptest` handlers and cover request encoding, error mapping and polling. They also cover the mock's own state machine.
- **Acceptance tests** (`internal/provider`) use `terraform-plugin-testing` with the `terraform` binary on `PATH`. `TestMain` starts the mock in-process, and because that costs nothing, `TF_ACC` is on by default. They cover:
  - create
  - in-place update of `backup_policy.retention`
  - in-place resize and rename, polling through `updating`
  - a `tier` change planned as a replacement, which yields a new ID and deletes the old database
  - import
  - a database deleted out of band
  - validation errors
  - the access key lifecycle: the secret survives updates and refreshes, and is replaced when `database_id` changes
  - verification on the mock that everything is gone after destroy
- **Smoke test** (`scripts/smoke.sh`, port `8089`, override with `PORT=`) runs `init`, `plan` and `apply`, then checks for an empty plan. It then does an in-place retention update and checks for an empty plan, replaces the tier and checks for an empty plan, and finally destroys everything and confirms via `curl` that the mock is empty.

## Resource behaviour

`lsmrust_database`
- `create` waits until the control plane reports `ready`. The timeout is 10 minutes, with a poll every 500ms. Transient errors while waiting (5xx, 429, refused or reset connections, timeouts) are retried until the deadline. Permanent ones, such as TLS certificate errors or an unknown host, fail immediately, and the wait gives up if the control plane stays unreachable for a full minute. Retries are logged at `TF_LOG=WARN`. If the wait fails, the ID is already saved, so the resource is tainted rather than orphaned.
- `name`, `resource_limits` and `backup_policy` update in place. A resize waits until the database is `ready` with the new limits.
- If an update fails, state is reset to what the control plane reports (or to the prior state if it cannot be read), so values that were never applied are not saved.
- Refresh warns if the control plane reports the database as `failed` or in an unknown status. `pending` and `updating` are treated as normal. Replace a failed database with `terraform apply -replace=<address>`.
- `tier` forces replacement. Replacing a database also replaces any `lsmrust_access_key` that references it, since the key's `database_id` changes, so the keys get new secrets.

`lsmrust_access_key`
- `scopes` is a set, so order does not matter. It updates in place. `database_id` forces replacement.
- `secret` is sensitive and only returned by the API at creation. The provider keeps it from state on every read, so refreshes never blank it. Imported keys have a null `secret`.

`404` handling
- A resource is dropped from state only when the control plane answers `404` with its own JSON error body. A `404` from anything else, such as a proxy or a wrong base path in `endpoint`, fails the refresh instead, so state is never silently wiped.

## Stubbed vs real

| Piece | Status |
|---|---|
| Provider, schema, CRUD, polling, import | Real |
| HTTP client | Real, written against the mock's API contract |
| Control plane | **Mock.** No lsm-rust processes, hosts, networking, storage or backups are created. `status` flips on a timer |
| Authentication | Static bearer token check only |

## Limitations

- No in-place `shared` to `dedicated` migration. A tier change destroys and recreates the database, including its data once a real backend exists.
- `backup_policy` values are passed through unvalidated. The cron and retention syntax is not checked.
- Single-line HCL blocks can hold only one argument, so `resource_limits { memory_mb = 4096, disk_gb = 100 }` is not valid HCL. Use multi-line blocks.
- No data sources, no `timeouts` block, and no registry release.
